## Decisions
- **Cache Components OFF.** Pages that read settings/orders are dynamic (`export const dynamic = 'force-dynamic'` where Next would otherwise prerender). This avoids Suspense/`'use cache'` requirements for a small dynamic site. Settings are read once per server render through React `cache()` (`src/lib/settings.ts`). Exception, owner-approved 2026-11-27: `/` and `/how-it-works` are ISR (`export const dynamic = 'force-static'` + `export const revalidate = 3600`): built once, served from the CDN cache, rebuilt at most hourly and right after an admin settings save (`revalidatePath('/', 'layout')` in `src/app/admin/actions.ts`). `force-static` makes `cookies()`/`headers()`/`searchParams` empty on those two pages, so they must never read per-request data. A Supabase outage during a rebuild throws, so Next keeps the last good page (and a build fails); a settings row that is missing or invalid still bakes the default settings in until the next rebuild (`reportError` raises the alarm). A settings edit made directly in the database shows within the hour. Every other page and route is still rendered per request.
- **Hosting = Vercel + Supabase.** The site is deployed on Vercel (`vercel.json`: region `bom1`, one daily cron) with `STORAGE=supabase`: Postgres tables plus a private bucket, called with plain `fetch` and the secret key (no SDK), see `src/lib/storage/supabase.ts`. `STORAGE=local` (files under `DATA_DIR`, default `./data`) is for development, unit tests and e2e. The `StorageAdapter` interface in `types.ts` is the seam between the two; `docs/ARCHITECTURE.md` has the path table.
- **Uploads on Vercel are direct.** Vercel caps request and response bodies at 4.5 MB, so the browser asks `POST /api/upload/direct` for a one-time signed URL, PUTs the file straight to the bucket, then calls `POST /api/upload/direct/commit`, where the server reads the stored bytes back and checks size and magic bytes. With local storage the first call answers `mode: 'server'` and the browser uses the multipart `POST /api/upload`. Admin downloads redirect to 60-second signed links for the same reason.
- **Rate limiting is in-memory and per instance.** On Vercel every serverless instance keeps its own counters, so the limits in `src/lib/rate-limit.ts` are a per-instance guard, not a site-wide quota. Site-wide limiting of `/api/upload/direct` and `/api/orders` is the job of a Vercel Firewall rate-limit rule (a project setting, not in this repo).
- **pdf-lib runs on both sides.** The server uses it to read uploaded PDFs and to build the sheet. The browser imports it lazily (never at module top level) only to read a PDF's TrimBox, so the preview size equals the server's `TrimBox ?? CropBox ?? MediaBox`.
- **Turnstile is half-wired.** `POST /api/orders` verifies a token when `TURNSTILE_SECRET_KEY` is set, but no page renders a widget or sends one. Keep the secret unset until a client widget exists.

## Known traps
- Phone JPGs: EXIF orientation. Browser `createImageBitmap(file, { imageOrientation: 'from-image' })`; server `sharp().rotate()`. The aspect ratio must come from the oriented image.
- PDF boxes: pdfjs uses CropBox + /Rotate for the viewport; pdf-lib `embedPage` uses MediaBox unless you pass `boundingBox`. Use TrimBox ?? CropBox ?? MediaBox on both sides.
- pdf-lib `drawImage` with `rotate` rotates about the image's lower-left corner — offset x/y by the rotated dimensions.
- Embed the artwork once, draw N times. Embedding per cell multiplies file size by N.
- `<input type="number">` misbehaves with Arabic keyboards. Use `type="text" inputMode="decimal" dir="ltr"` and `parseCm()`.
- Vercel function request and response bodies are limited to 4.5 MB. Files therefore never pass through a function on Vercel (direct upload, signed download links; see Decisions); the multipart `POST /api/upload` serves `STORAGE=local` only. Keep the JSON order route file-free.
- `pnpm purge` is a pnpm built-in (an alias of `pnpm clean`, which removes `node_modules`). The retention script is therefore named `purge:orders`.
- A page's own `notFound()` inside a dynamic route answers with an error shell (`<html id="__next_error__">`) whose flight data names the route and its params; an unknown URL gets the prerendered `/_not-found` page instead. A proxy `NextResponse.rewrite()` always adds `x-middleware-rewrite: <target>` to the response (and rewriting to `/_not-found` itself serves it with `Cache-Control: s-maxage=31536000`). To make a URL answer exactly like an unknown one, let it match no route (`NextResponse.next()`). The staff page is built this way (`docs/ARCHITECTURE.md` section 1).
- `next dev` echoes each 404's own URL in the flight data (`"c":["","some","path"]`); a production build does not. Compare 404 bodies against a production build, or strip that field first.

## Rate limiting / TRUST_PROXY
- `x-forwarded-for` is client-controlled, so by default (`TRUST_PROXY=0`) it is **ignored**: every route uses one global bucket with limits x20 (uploads 400/h, orders 100/h, log 1200/h, admin login 200/15 min).
- Per-IP limiting (uploads 20/h, orders 5/h, log 60/h, login 10/15 min) needs a reverse proxy that appends to `x-forwarded-for` (nginx/Caddy, or Vercel) and `TRUST_PROXY=<hops>`; the n-th value from the END of the header is used (`1` = a single proxy in front; production on Vercel runs with `TRUST_PROXY=1`).
- `/api/track` is limited to 300 events per hour per visitor hash in both modes.
- Request bodies are capped before parsing: upload `maxUploadBytes + 64 KiB` with a mandatory `Content-Length` (and a byte-capped stream read), orders 64 KiB, log 8 KiB, direct-upload start/commit and track 4 KiB.
- Public order/upload/log paths read `getOrderEnv()` only; `ADMIN_PASSWORD`/`SESSION_SECRET` (`getAdminEnv()`) are needed for /admin alone. Placeholder values (`change-me...`) are rejected.

## OpenAI image and text API (AI sticker designer)
Findings from the 2026-11-21 spike (14 images) and the code in `src/lib/ai/`. Plain `fetch`, no SDK; the base URL is `OPENAI_BASE_URL` (default `https://api.openai.com/v1`) so tests can point at a mock.
- **Models.** The account has `gpt-image-2.6-flare` (used: about 11-18 s per image) and `gpt-image-2.6-sunburst` (about 30 s, no clear quality gain for stickers), plus older 2.5 / 2 / 1.5 / mini. A Vercel function has `maxDuration = 60` and the call has a 50 s timeout, so Flare fits and Sunburst would be risky. Text extraction uses `gpt-5.4-mini`.
- **Sizes.** `size` is `WIDTHxHEIGHT`; both sides must be multiples of 16, the area at least 655,360 px, and the long side at most 3 times the short side. The site therefore asks for at most 3:1 and extends a longer rectangle itself (see `docs/ARCHITECTURE.md`, AI designer, Models). A bad value is a 400 (the spike's 9999 was rejected for divisibility). The site asks for 1024x1024, or long side 1024 with the other side `round(1024 / aspect / 16) * 16`, grown in steps of 16 until the area is large enough. 2048x2048 was accepted; the upper limit is unknown and irrelevant at 1024.
- **`background`.** `transparent` or `opaque`. Circle and custom stickers use `transparent`: for a circle, "fill the whole square" with `opaque` put text too close to the circle edge, so the circle is drawn on transparency and flattened onto white server-side. Rectangles use `opaque`. With no `background` the model may still return transparent corners on its own.
- **Alpha quirk.** Generated PNGs have "opaque" pixels at alpha 253-254, never 255, and fully transparent pixels carry dark RGB, not white. The site's decode treats any alpha below 255 as "has alpha", so `normaliseGenerated()` (`src/lib/ai/normalise.ts`) cleans every result before it is stored: flatten onto white for circle and rect; for custom alpha >= 250 becomes 255 and alpha <= 8 becomes 0 with white RGB.
- **Reference images.** With references the call is `POST /images/edits`, multipart, one `image[]` part per image (up to 5), and it accepts `output_format: png`, `background`, `size`, `quality` like `/images/generations`. References are re-encoded first (auto-orient, long side 1024, metadata stripped). The edits call kept a character recognisable.
- **Response.** `data[0].b64_json` (PNG). A safety refusal is an HTTP 400 with `error.code = moderation_blocked` (or a message about the safety system / content policy); the site maps it to `refused` and gives the use back. Never put an OpenAI response body in a log or a report: it can echo the key or the customer's text.
- **Responses API (text extraction).** `POST /responses` with `instructions` (fixed rules plus worked examples), `input` (the customer's message, as data), `text.format = { type: 'json_schema', strict: true, schema }` and `store: false` (the message can hold names and phone numbers; OpenAI must not keep it). Strict mode needs `additionalProperties: false` and every property in `required`. The answer is under `output[].content[]`, an item with `type: 'output_text'` (or a `refusal` item). The extractor is the weak point of quality: without examples it once took the customer's description of the artwork as text to print, so keep the examples and the review box.
- **The model ignores size hints for text.** "Letters at least N % tall" is not obeyed when there is a lot of text (6 lines on a 3 cm sticker gave letters of about 2 mm), so the customer is warned by the text-capacity check (`src/lib/ai/text-capacity.ts`: a warning and a size recommendation, never a block); the prompt alone cannot keep the text readable.
- **Cost.** About USD 0.05 per 1024x1024 `high` image (third-party price list, not verified on the account); references add a little. The daily caps in settings (5 per IP, 300 per site) bound the worst case at roughly USD 16 a day; set a monthly budget on the OpenAI account too.
